# Plan 01: Interactive Selector Controller and Styles

## Objective
<objective>
Create the inline format-selector UI module and CSS so the four clock segments become the selector surface: each segment has a stable DOM identity, opens a single anchored dropdown, exposes keyboard/touch interactions, and matches the existing atmospheric glass styling without adding a new UI system.
</objective>

## Tasks

<task id="14-01-01" type="create">
<title>Create `src/formats/selectors/ui.js` as the single selector manager</title>
<read_first>
- src/formats/ui/stdtime-picker.js — existing format change event name, config save flow, and label mapping pattern
- src/location/ui.js — dropdown dismissal, Escape handling, and one-surface-at-a-time interaction patterns
- src/formats/config.js — `getFormat()` and `setFormat()` API

- .planning/phases/14-format-selector-ui-integration/14-UI-SPEC.md — DOM, interaction, and accessibility contract
</read_first>
<action>
Create `src/formats/selectors/ui.js` and import `./styles.css` from that module.

Implement this exact module surface:

1. Export `FORMAT_CHANGE_EVENT = 'beatclock:formatchange'`.
2. Export `initFormatSelectors(container)`.
3. Export `renderFormatDisplay(values)`.

Inside the module, implement the following concrete behavior:

1. Define a fixed component metadata map for `year`, `date`, `stdTime`, and `solarTime` with:
   - visible hover labels: `Year`, `Date`, `Standard Time`, `Solar Time`
   - aria labels: `Change Year format`, `Change Date format`, `Change Standard Time format`, `Change Solar Time format`
   - format label maps:
     - year: `holocene -> Holocene`, `gregorian -> Gregorian`, `meghalayan -> Meghalayan`, `custom -> Custom`
     - date: `gregorian -> Gregorian`, `chinese -> Chinese`, `longitudinal -> Longitudinal`
     - stdTime: `24h -> 24h`, `decimal -> Decimal`, `longitudinal -> Longitudinal`
     - solarTime: `24h -> 24h`, `decimal -> Decimal`, `longitudinal -> Longitudinal`, `descriptive -> Descriptive`
2. `initFormatSelectors(container)` must:
   - store the `#beats-container` reference once
   - create four stable span nodes with class `clock-component` and `data-component` values `year`, `date`, `stdTime`, `solarTime` if they do not already exist
   - set `tabindex="0"` and `role="button"` on each span
   - set `aria-label` from the metadata table
   - attach click and keydown handlers exactly once
   - keep one shared dropdown element appended to `document.body`
3. Use `document.createElement()` for dropdown construction. Do not use `innerHTML` for option rows.
4. Dropdown behavior must be concrete:
   - only one dropdown open at a time
   - clicking a component opens its dropdown below the component
   - if `anchorRect.bottom + dropdownRect.height + 8 >= window.innerHeight`, position it above instead
   - clicking outside closes it
   - pressing `Escape` closes it and returns focus to the owning component
   - selecting an option calls `setFormat(componentId, formatId)`, dispatches `new CustomEvent(FORMAT_CHANGE_EVENT, { detail: { componentId, formatId } })`, and closes the dropdown immediately
5. Active option row must be visually marked by adding class `is-active` and a trailing `span` with text `✓`.
6. `renderFormatDisplay(values)` must update the existing four span nodes' `textContent` only. It must not recreate the spans or replace the `#beats-container` children wholesale once the structure exists.
7. Export nothing else.

Keep all state module-local: active component ID, dropdown element, owner element, and document-level cleanup references. This is a small imperative controller, not a class hierarchy.
</action>

<threat_model>
## Threats

- Injecting option labels with `innerHTML` would create unnecessary DOM injection risk.
- Recreating the whole clock tree on every tick would drop listeners and create stale focus state.

## Mitigations

- Build dropdown rows with `document.createElement()` and assign visible labels with `textContent`.
- Keep stable component nodes and update only their `textContent` during rerenders.

## Residual Risks

- Low risk of event-listener leakage if document-level dismissal handlers are attached more than once. Keep initialization idempotent.
</threat_model>
