# Plan 02: Registry-Driven Clock Pipeline Integration

## Objective
<objective>
Replace the hard-coded clock string in `src/index.js` with a format-aware pipeline that renders the four display segments through the registry, preserves the existing sky/moon/location/alarm loops, restarts cadence when the Standard Time format changes, and keeps renderer failures isolated to their individual components.
</objective>

Update `src/index.js` with these exact integration changes:

1. Remove the old Standard Time picker import and initialization:
   - delete `initStdTimePicker`
   - delete `STDTIME_FORMAT_CHANGE_EVENT`
   - delete `initStdTimePicker()` call
   - replace the old event listener with the new `FORMAT_CHANGE_EVENT`
2. Add imports from `src/formats/selectors/ui.js`:
   - `FORMAT_CHANGE_EVENT`
   - `initFormatSelectors`
   - `renderFormatDisplay`
3. Keep `getActiveStdTimeFormat()` and `getActiveTickRate()` but make `getActiveStdTimeFormat()` validate through `getRenderer('stdTime', formatId)` exactly as it does today.
4. Delete `getStdTimeString(now)` entirely. Standard Time must now be produced inside the shared render pipeline, not as a separate one-off helper.
5. Add a new helper `getSafeFormat(componentId, fallbackFormatId)` that:
   - reads the saved format via `getFormat(componentId)`
   - returns the saved value only if `getRenderer(componentId, savedFormatId)` exists
   - otherwise returns the explicit fallback
6. Add a new helper `renderClockComponents(data)` that renders in this exact order to preserve the solar/date suffix contract:
   - `year`
   - `solarTime`
   - `date`
   - `stdTime`
7. Use one shared `data` object equal to `{ now, ...composeResult }` and separate per-component opts objects:
   - year opts: `{}`
   - solar opts: `{ meridianOffset: 0 }`
   - date opts: `{ solarDateDiffsStdDate: solarOpts.solarDateDiffsStdDate ?? null }`
   - stdTime opts:
     - `24h` => `{ showSeconds: true, meridianOffset: 0 }`
     - `decimal` => `{ meridianOffset: 0 }`
     - `longitudinal` => `{ meridianOffset: 0 }`
8. Wrap each renderer call in its own try/catch and on failure:
   - return `'??'` for `year` or `date`
   - return `'??:??'` for `stdTime` or solar 24h when the renderer itself already uses that fallback
   - log `console.warn('Failed to render ${componentId}:', error.message)`
   - continue rendering the other components
9. Replace the current `clockText` string assignment with:
   - `initFormatSelectors(document.querySelector('#beats-container'))` during boot
   - `renderFormatDisplay({ year, date, stdTime, solarTime })` from inside `updateClock()`
10. Keep the existing sky gradient and moon indicator updates exactly where they are today.
11. Rename `handleStdTimeFormatChange()` to `handleFormatChange()` and keep its behavior exactly:
   - `updateClock(currentLocation)`
   - `restartDisplayLoop()`
   - `restartAlarmLoop()`

Do not move app orchestration out of `src/index.js`. The selector module owns UI interaction only; `src/index.js` remains the single coordinator for rendering and live loops.

<threat_model>
## Threats

- A full-tree rerender on every tick could drop listeners and leave the dropdown orphaned.
- Sharing one mutable opts object across renderers could create hidden cross-component state bugs.

## Mitigations

- Keep the four display spans stable and update only their text values through `renderFormatDisplay()`.
- Use distinct opts objects per component and copy the solar/date diff explicitly into the date opts.

## Residual Risks

- Low integration risk around fallback strings if a renderer throws before returning its own error value. Keep the try/catch localized per component.
</threat_model>
