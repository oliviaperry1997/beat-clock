# Plan 03: Selector Interaction and Cadence Regression Tests

## Objective
<objective>
Add focused jsdom integration coverage that proves the new inline selector UI renders four interactive segments, opens and closes a single dropdown correctly, persists selections, rerenders immediately, and still restarts the live display/alarm cadence when the saved Standard Time format changes.
</objective>

## Tasks

<task id="14-03-01" type="create">
<title>Create `tests/integration/format-selector-ui.test.js` for the new selector surface</title>
<read_first>
- tests/integration/stdtime-tick-rate.test.js — current jsdom module-mocking pattern for `src/index.js`
- tests/integration/composer.test.js — current compose expectations
- src/index.js — post-Plan-02 wiring surface
- src/formats/selectors/ui.js — exported selector API and DOM class names
- src/formats/config.js — storage key and config shape
</read_first>
<action>
Create `tests/integration/format-selector-ui.test.js` with `// @vitest-environment jsdom` and reuse the same mocking pattern used in `tests/integration/stdtime-tick-rate.test.js` for:

- `compose`
- `initLocationSystem`
- `initAlarmEngine`
- `setDismissCallback`
- `handleMissedAlarms`
- `initAlarmSystem`
- `invalidateCache`
- `initConverterPanel`
- `getSkyGradientColors`

The mocked `compose()` result must include enough data for all four components to render, including `solarTime`, `lunisolar`, and `holocene`.

Implement these exact test cases:

1. `renders four interactive clock segments on load`
   - import `../../src/index.js`
   - assert `[data-component="year"]`, `[data-component="date"]`, `[data-component="stdTime"]`, and `[data-component="solarTime"]` all exist
   - assert each has `role="button"` and `tabindex="0"`
2. `does not render the legacy stdtime picker`
   - assert `document.getElementById('stdtime-picker')` is `null`
3. `opens a single dropdown for the clicked component`
   - click the `year` segment
   - assert one `.format-selector-dropdown` exists and contains `Holocene`, `Gregorian`, `Meghalayan`, and `Custom`
   - click the `date` segment
   - assert still only one dropdown is visible and it now contains the date format labels
4. `selecting a new format persists and rerenders immediately`
   - start with saved config year=`holocene`
   - click the `year` segment, choose `Gregorian`
   - assert localStorage value for `beatclock:formats` now stores `components.year = 'gregorian'`
   - assert the year segment text changes away from the Holocene output on the same event cycle
5. `dropdown closes on outside click and Escape`
   - open a dropdown
   - dispatch document click outside it and assert it closes
   - open again, dispatch `keydown` with `key: 'Escape'`, assert it closes and focus returns to the owner segment
6. `renderer failure stays component-scoped`
   - mock one renderer path through compose data so exactly one component throws or returns invalid input
   - assert the failing segment shows a fallback while the other three segments still contain non-empty text

Use concrete assertions against the DOM and storage rather than snapshot tests.
</action>

</task>

<threat_model>
## Threats

- Tests could pass while still depending on removed DOM nodes if old assertions are left behind.
- Dropdown behavior could regress silently without a direct single-open assertion.

## Mitigations

- Update the tick-rate test to interact through `[data-component="stdTime"]` only.
- Add explicit assertions for dropdown uniqueness, persistence, and component-scoped fallbacks.

## Residual Risks

- Visual polish still needs manual browser verification because jsdom does not validate hover appearance or media-query behavior.
</threat_model>
